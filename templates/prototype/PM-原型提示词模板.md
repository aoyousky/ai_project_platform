# PM 原型提示词模板 v1.1

> 用途：让 PM 用一段结构化提示词，直接生成"能拿去评审"的高保真原型。
> **上游**：先填 `PM-场景切片表.md`——把需求拆成 ≤7 个场景并聚合成页面，再来写这里的提示词。跳过切片直接写提示词，百分之百产出"万能页"。
> 使用方法：复制「第二部分」的模板 → 填空 → 一次贴给 AI。首次生成只追求结构对，视觉靠第 6 节的 3 轮迭代收敛。
> **填不动某一段时，去第五节抄例句**——那里每段都有"弱写法 → 强写法"对照，以及生成跑偏后该怎么说话。

## 一、为什么是五段式

AI 画得丑，通常不是模型不行，是**约束没传进去**：不知道业务语境（猜）、不知道信息架构（自己编）、不知道设计系统（用模板配色）、不知道边界（自由发挥）。五段式就是把这四件事一次说清，再加一段"反向约束"堵住 AI 的惯性审美。

| 段 | 解决什么 | 缺了会怎样 |
|---|---|---|
| ① 角色与目标 | 让 AI 站在正确视角 | 生成"通用后台模板" |
| ② 业务语境 | 真实用户、真实任务、真实数据量 | 界面像 demo，字段虚构 |
| ③ 信息架构 | 页面结构、字段、状态 | 自己编分区、漏状态 |
| ④ 约束 | 设计 token + 技术栈 + 密度 | 视觉漂移、与现有产品不一致 |
| ⑤ 反例清单 | 堵住 AI 的默认审美 | 卡片套卡片、渐变紫、图标堆砌 |

## 二、提示词模板（复制这段填空）

```text
# ① 角色与目标
你是我们产品的资深界面设计师，熟悉 B 端后台的信息密度要求。
本次要产出的页面：【页面名称】。
唯一主行动：【用户在这一页最重要的一件事】。
使用者：【角色】，日均使用【N】次，单次停留【时长】。

# ② 业务语境
业务场景：【谁，在什么触发条件下，要完成什么任务，完成后进入哪一步】。
数据规模：列表常态【N】条，峰值【N】条；单条记录约【N】个字段。
真实数据特征：【字段的真实长度/格式，例：订单号 ORD-10001 共 9 位；金额为分，展示为元并千分位】。
上下游：【从哪个页面进入，操作后跳转到哪个页面】。

# ③ 信息架构（照抄下表，不要自行增减分区）
页面分区，从上到下：
1. 【页头：标题 + 面包屑 + 返回】
2. 【筛选区：字段 A/B/C + 查询/重置】
3. 【主数据区：表格，列依次为 ...】
4. 【分页 / 批量操作】
主行动按钮位置：【右上角 / 表格行内】。
必须存在的状态：
- 空状态：说明【没有数据的原因】+ 给出【下一步动作】
- 加载中：骨架屏，不转圈遮罩
- 错误：错误码 + 重试按钮
- 无权限：提示申请入口
- 超限：提示缩小范围
字段与数据对应：【字段名 → 数据来源 → 是否可编辑 → 校验规则】

# ④ 约束
【设计 token 见下表，必须严格使用，不得自创颜色与圆角】
- 主色 / 成功 / 警告 / 危险：...
- 字号阶梯：仅 3 级（页面标题 / 区块标题 / 正文），正文不小于 12px，行高 1.5
- 间距：4 的倍数，区块间 24px，表单行间 16px
- 圆角：卡片 8px，按钮 6px，输入框 6px，禁止 ≥ 16px
- 阴影：仅一层，透明度 ≤ 8%，禁止发光
- 图标：单一线性风格，16/20px 两档，禁止 emoji
- 密度：表格行高 44px，一屏可见 ≥ 10 行
技术约束：目标框架【Vue 3 + Element Plus / 其他】；断点【1440 主，1024 兼容】。
文案要求：中文，动宾结构，按钮 ≤ 4 字，禁止机翻腔，禁止英文占位。

# ⑤ 反例清单（以下做法一律不要）
- 不要卡片套卡片；不要每个数字都配彩色图标 + 等宽圆角卡片
- 不要渐变、玻璃拟态、发光边框
- 不要主次行动同权重（一屏只允许一个实心主按钮）
- 不要在表格里塞进度条、头像、标签云
- 不要空状态只写"暂无数据"
- 不要圆角 > 16px、阴影重、配色超过 3 个色相
- 不要用 emoji 当图标，不要混用线性与面性图标
- 不要虚构业务字段，字段只能来自第 ③ 段
- 不要省略加载/错误/无权限状态
```

## 三、设计 token 占位表（填一次，长期复用）

| Token | 你的值 | 说明 |
|---|---|---|
| 主色 | `#______` | 主按钮、选中态、链接 |
| 成功 / 警告 / 危险 | `#__ / #__ / #__` | 状态语义，不得互换 |
| 页面底色 | `#______` | 通常 F5F7FA 一类的浅灰 |
| 卡片底色 | `#______` | 纯白或与底色差 ≤ 4% |
| 主文字 / 次文字 / 提示文字 | `#__ / #__ / #__` | 三档足够，不要更多灰 |
| 字号阶梯 | `__/__/__` | 例：20 / 14 / 13 |
| 圆角 | `__px` | 卡片 8，控件 6 |
| 栅格 / 内容最大宽 | `__ / __px` | 例：24 栅格，1440 内容区 1160 |
| 表格行高 | `__px` | B 端建议 44–48 |
| 图标库 | `______` | 只允许一个来源 |

> 这张表是"视觉不漂移"的关键：连续生成三个页面，靠的就是同一份 token。

## 四、完整示例（订单查询页）

```text
# ① 角色与目标
你是我们产品的资深界面设计师，熟悉 B 端后台的信息密度要求。
本次要产出的页面：订单查询。
唯一主行动：按条件查到目标订单并进入详情。
使用者：客服专员，日均使用 80 次，单次停留 30 秒内。

# ② 业务语境
业务场景：客服接到用户来电，凭订单号或手机号查询订单，确认状态后进入详情处理售后。
数据规模：列表常态 20 条/页，峰值单账户 3000 条；单条记录 8 个字段。
真实数据特征：订单号 ORD-10001 共 9 位；金额以分存储，展示为元并千分位；时间格式 YYYY-MM-DD HH:mm。
上下游：从工作台进入；点击行进入订单详情页。

# ③ 信息架构
1. 页头：标题「订单查询」+ 面包屑「工作台 / 订单」
2. 筛选区：订单号（输入）、手机号（输入）、下单时间（日期范围）、订单状态（下拉）、查询、重置
3. 主数据区：表格，列依次为 订单号 / 下单时间 / 商品名称 / 实付金额 / 订单状态 / 支付方式 / 操作
4. 分页：每页 20 条，显示总数
主行动按钮：右上角「导出」为次要按钮，主按钮为筛选区「查询」
必须存在的状态：空状态（无匹配订单，提示"换个订单号或放宽时间范围"）、加载中（骨架屏）、错误（ERR-5003 + 重试）、无权限（申请查看权限入口）、超限（时间范围 > 90 天时提示缩小范围）
字段对应：订单号←order_id 只读；金额←amount(分)→元 只读；状态←status 枚举（待支付/已支付/已发货/已完成/已取消）

# ④ 约束
主色 #1F6FEB；成功 #12A150；警告 #D97706；危险 #DC2626；页面底 #F5F7FA；卡片 #FFFFFF；
主文字 #1F2329；次文字 #606266；提示 #909399；
字号仅 20/14/13；正文行高 1.5；区块间距 24px；卡片圆角 8px，控件 6px；
阴影单层 8% 透明度；图标 16/20px 线性；表格行高 44px，一屏 ≥ 10 行。
技术约束：Vue 3 + Element Plus，1440 主，1024 兼容。文案中文动宾结构，按钮 ≤ 4 字。

# ⑤ 反例清单（同上，粘贴即可）
```

## 五、优秀实践示例语库（可直接抄）

写提示词只有一个诀窍：**把形容词换成数字，把"要什么"换成"不要什么"**。形容词是 AI 的自由发挥空间，数字和禁令才是它能执行的约束。

下面每段都给"弱写法 → 强写法"，弱的是绝大多数人的默认写法，强的是可以直接粘贴的。

### 5.1 角色与目标段

| 弱写法 | 强写法（复制这句） | 为什么有效 |
|---|---|---|
| 你是一个专业的 UI 设计师 | 你是我们产品的资深界面设计师，做 B 端后台五年，习惯在有限空间里塞高密度信息。你的判断标准是「客服能不能 30 秒内查完一单」，不是「页面好不好看」。 | 给了 AI 一个可判定的成功标准，而不是一个身份标签 |
| 帮我设计一个订单页面 | 这一页只服务一个动作：**在不知道订单号的情况下，用手机号定位到最近一笔订单**。其他一切（统计、报表、推荐）都不属于这一页。 | 用"只服务一个动作"锁死范围，比"唯一主行动"更难被忽略 |

**句式模板**：`你是【角色】，你的判断标准是【可判定的业务结果】，不是【审美形容词】。`

### 5.2 业务语境段（拉开差距最大的一段）

弱写法：「这是一个订单查询页面，给客服用的。」——AI 只能生成通用后台模板。

强写法（挑 2–3 条贴进去，效果立刻不同）：

- **写身体状态，不写岗位职责**：「客服左手拿电话、右手单手操作，主路径不能超过 3 次点击。」
  → AI 会自动做出大点击区、少层级、无悬停依赖的交互。
- **写使用频次，不写"高频"**：「每天看这个页面 80 次，第 81 次她要的是『和上次一样』，所以筛选条件必须记住上次选择。」
- **写数据的脏，不写"数据量大"**：「商品名最长 40 字会折行；金额存在 0 元和负数（退款）；状态有 5 种但 90% 是已支付。」
- **写真实的后续动作**：「财务会把这个页面截图贴进 Excel，所以关键数字要能被 1440 宽下的首屏完整框住。」
  → 这条约束了列宽和首屏高度，是纯靠"要专业"永远得不到的。
- **写被打断的场景**：「操作中途常被电话打断，所以已填的筛选条件不能因为超时被清空。」

### 5.3 信息架构段

| 弱写法 | 强写法（复制这句） |
|---|---|
| 页面包含筛选、列表、分页 | 分区固定为 4 块，**不允许新增第 5 块**：①页头 ②筛选（单行，超过 4 个条件折叠进「更多筛选」）③表格 ④分页。分区顺序即优先级，越靠上越高频。 |
| 表格放订单信息 | 列按「先确认身份、再做决策」排序：订单号、手机号、下单时间、金额、状态、操作；列宽按内容真实长度分配，不允许等宽。 |
| 状态用标签区分 | 状态列用「文字 + 圆点」表达，禁止彩色背景块——一屏 10 行彩色块会让人找不到重点。 |
| 空状态提示暂无数据 | 空状态必须回答两个问题：**为什么没有 + 我现在能做什么**。文案「没有查到匹配订单，换个订单号或放宽时间范围试试」，右侧给「清空筛选」按钮。 |
| 字段可能为空 | 空值统一展示「—」，不用空白——空白会被误读为加载失败。 |

### 5.4 约束段

约束必须有数量，没有数量的约束等于没写：

- 颜色只允许出现在三个地方：**主按钮、状态圆点、错误提示**，其余一律中性灰。
- 字号只有三档，相邻两档差 ≥ 2px，**不允许出现第四档**。
- 所有可点击元素点击区 ≥ 44×44，**包括只有图标没有文字的按钮**。
- 同一页面圆角只有两种值，出现第三种即视为错误。
- 信息密度优先：一屏 ≥ 10 行数据。**留白在这里不是美德，是浪费。**
- 按钮文案统一动宾结构、2–4 字，**禁用「确定 / 提交 / 保存」这类无信息量的词**，改成「保存订单 / 提交审核 / 导出对账单」。

> 最后一条最容易被忽略，但它对"这看起来像不像我们产品"的影响，比配色更大。

### 5.5 反例段

反例要写出**理由**，AI 才不会再犯：

- 不要做卡片式布局——这是数据密集列表，卡片会浪费 40% 横向空间。
- 不要给每个数字配彩色图标——图标在这里不承担识别功能，只是噪音。
- 不要渐变、玻璃拟态、发光——用户是 40 岁的财务，不是设计师。
- 不要在主按钮旁边放同等重量的次按钮——一屏只能有一个实心按钮，其余是幽灵按钮或文字按钮。
- 不要表格斑马纹 + 边框 + 分隔线三重分隔，**选一种**。

### 5.6 生成后的纠正话术（对症表）

原型一次就对的概率很低，真正决定效率的是**第二轮你怎么说话**。

| 你看到的 | 别这么说（AI 无法执行） | 就这么说（可直接复制） |
|---|---|---|
| 太花哨 | 「简洁一点」 | 去掉所有装饰性元素：渐变、阴影、彩色图标、卡片边框。层级只靠字号和字重区分。 |
| 太空、留白过多 | 「信息密度高一点」 | 表格行高 56→44，筛选区间距 24→16，一屏放到 10 行以上；**不新增任何元素**。 |
| 没有重点 | 「突出主按钮」 | 主按钮实心填充主色，其余按钮全改幽灵样式；标题字重 600、正文 400。 |
| 像套的模板 | 「做得像我们的产品」 | 参考这张图（附截图）的表格密度与留白节奏，但配色和圆角用我给的 token。 |
| 字段不对 | 「字段有问题」 | 只允许出现这 7 个字段：……，**删掉其余全部，不要补位**。 |
| 完全跑偏 | 「不是我要的」 | **停。先说你理解的主行动是什么，我确认后再改。** ← 这句最省时间 |
| 改一处坏两处 | 「别把别的改了」 | 保持布局、间距、颜色、文案全部不变，**只**调整表格列宽。 |

最后两行是从"AI 交付治理"里搬过来的：**没理解就停下来问，比闷头生成一百版都便宜**。

### 5.7 四类万用句式

| 类型 | 句式 | 用在哪 |
|---|---|---|
| 限定式 | 只……，不…… | 任何修改轮次，防止顺手改坏别的 |
| 保持式 | 保持【X】不变，只调整【Y】 | 3 轮迭代法的每一轮开头 |
| 兜底式 | 如果有不确定，先说出你的理解，不要自行决定 | 需求复杂、字段多时必加 |
| 判定式 | 如果做不到【X】，就退回【Y】，不要自己发明【Z】 | 约束冲突时，堵死 AI 的"创意" |

## 六、3 轮迭代法（别一次就想出终稿）

| 轮次 | 只改什么 | 追加提示词片段 |
|---|---|---|
| 第 1 轮 | **结构** | 「先只给线框级布局，灰阶，不要颜色和图标，我要确认分区与字段顺序」 |
| 第 2 轮 | **密度** | 「保持结构不变，把表格行高调至 44px，一屏放置 10 行以上，压缩筛选区高度到 56px」 |
| 第 3 轮 | **视觉** | 「保持结构与密度不变，套用我给的 token，只调整字号层级与留白，不要新增任何元素」 |

铁律：**一轮只改一个维度**。同时改结构和配色，你永远不知道是哪一处导致变丑，也就无法回收。

## 七、生成后自检 8 项（不过就别拿去评审）

- [ ] 主行动只有一个，且在首屏可见
- [ ] 5 个状态都在，空状态给了下一步动作
- [ ] 字段全部来自信息架构，没有 AI 虚构的字段
- [ ] 视觉只用了 token 里的颜色与圆角，没有自创
- [ ] 一屏可见行数达标，没有过度留白
- [ ] 文案全是中文动宾结构，无 Lorem、无英文占位
- [ ] 反例清单逐条对照，0 命中
- [ ] 1024 断点下不溢出、不错位

## 八、原型 → Spec Packet 对照（别让原型白做）

| 原型元素 | 转到 Spec Packet 的哪一段 |
|---|---|
| 页面分区 + 主行动 | 第 1 段 意图 |
| 每个交互的点击结果 | 第 2 段 验收断言 A-xx（Given/When/Then） |
| 5 个状态 | 第 3 段 边界与异常 E-xx |
| 字段对应表 | 第 4 段 数据契约 |
| token 与断点 | 第 5 段 非功能约束 |
| 明确不做的事 | 第 7 段 Non-goals |
| 场景切片表里被砍掉的场景（S-xx） | 第 7 段 Non-goals（现成的，不用重写） |
| 关键页截图 | 第 8 段 Golden Samples 配图 |

> 原型是**证据**，不是规格。它能大幅提升断言质量，但"能点通"不等于"可交付"——门槛仍是那 5–12 条可判定断言。
