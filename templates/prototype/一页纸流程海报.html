PM 原型三件套 · 一页纸流程

从一句话需求，到 AI 能直接交付的规格

四个步骤 · 三份模板 · 每步一道门禁。跳过任何一步，得到的都是「看起来很精致，但用不了」的原型。

一句话原则
把形容词换成数字，
把「要什么」换成「不要什么」。
01

场景切片

PM 独立完成 · 30 分钟
输入

一句话需求

做什么

拆成 ≤7 个「角色 × 触发 × 目标 × 判定」的场景，再聚合成页面清单

产出
  • 场景表 S-01 … S-07
  • 页面清单 P-01 … P-03
  • 标出本轮只做 1 页
提示先写 10 条再删到 7 条；砍掉的场景别丢，它们就是 Non-goals。
门禁四维填全 · 角色唯一 · 主路径 ≤3 点击 · 场景 ≤7
→
02

原型生成

PM · 3 轮迭代 × 1 页
输入

只输入这一页对应的场景，不是全部

做什么

五段式提示词一次生成；三轮只改一个维度：结构 → 密度 → 视觉

产出
  • 高保真原型，主路径可点通
  • 5 个状态齐全：空 / 加载 / 错误 / 无权限 / 超限
提示跑偏了就说：「停。先说你理解的主行动，我确认后再改。」
门禁自检 8 项全过 · 字段零虚构 · token 零自创
→
03

断言化

PM + 业务方 · 半天
输入

原型的每页交互与 5 个状态

做什么

把交互改写成可判定断言，补齐边界、数据契约、Non-goals

产出
  • Spec Packet：A-xx / E-xx / 契约 / Non-goals
  • 3 个正例 + 1 个反例
提示转不成断言的，列入 UNVERIFIABLE 清单，禁止臆造。
门禁Then 只能是状态码 / 返回值 / 阈值 / 错误码
→
04

AI 交付

Agent + Dev
输入

签字版 Spec Packet，唯一依据

做什么

Agent 生成、人评审；规格没写清就停下出澄清单，不许猜

产出
  • 代码 + 评测集全绿
  • 溯源 trace.yaml
提示IM 记录、会议纪要、口头补充，都不是交付依据。
门禁12 项 review 通过 · 无溯源不得报告完成
三条红线（踩了必返工）
  1. 不切片直接写提示词，必然产出「万能页」——一页塞五个角色，最后谁都不好用
  2. 一次只生成一页。三页塞进一段提示词，AI 平均分配注意力，三页都平庸
  3. 原型是证据，不是规格。「能点通」不等于「可交付」，门槛仍是那 5–12 条断言
三个最常见的坑
  • 角色写「用户」「管理员」——太泛，AI 无法据此做任何设计决策
  • 触发时机留空——AI 会按「打开系统」设计，做出首页式布局
  • 成功判定写「体验流畅」——不可判定，等于没写
30 分钟工作法
1不看界面，先写 10 条场景
2按四条规则删到 ≤7 条
3聚合页面，标出本轮 1 页
第一遍几乎一定会把「功能」当成「场景」，所以先多写再删。砍掉的场景别丢，它们就是 Spec Packet 的 Non-goals。
