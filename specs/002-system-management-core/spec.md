## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用户全生命周期管理 (Priority: P1)

系统管理员可以在统一用户列表中按用户名称、昵称、手机号码、状态、所属部门与创建时间筛选用户，查看分页结果；可以新增用户、编辑用户资料、删除用户、重置密码、启用/停用账号、批量导入用户、导出用户数据，并为用户分配角色。用户列表左侧显示部门树，点击部门后只显示该部门及其下级部门的用户。

**Why this priority**: 用户是权限、组织与业务数据的核心主体。没有用户管理，角色授权、部门负责人、岗位分配都无法闭环，因此必须先交付。

**Independent Test**: 在已登录且具备 `system:user:*` 权限的账号下，独立完成“筛选用户 → 新增用户 → 编辑用户 → 分配角色 → 重置密码 → 启用/停用 → 删除用户 → 导出”的完整链路；每一步的结果都能在列表中或重新查询后得到验证。

**Acceptance Scenarios**:

1. **Given** 管理员进入用户管理页，**When** 输入用户名称并点击搜索，**Then** 列表只显示匹配的用户，分页总数同步更新，重置按钮可恢复默认查询条件。
2. **Given** 管理员点击新增用户，**When** 填写必填项并提交，**Then** 新用户出现在列表中；用户名、手机号、邮箱等重复或格式非法时，页面展示后端返回的明确错误且不新增记录。
3. **Given** 列表中存在用户，**When** 管理员编辑该用户并保存，**Then** 列表与详情显示更新后的资料；修改用户名、密码等仅允许在新增时填写的字段不出现在编辑态。
4. **Given** 管理员选择一个用户并分配角色，**When** 勾选角色并提交，**Then** 该用户的角色列表即时更新，重新进入授权页仍保持勾选结果。
5. **Given** 管理员对用户执行重置密码，**When** 输入符合规则的新密码并确认，**Then** 操作成功；新密码不符合规则时展示校验错误。
6. **Given** 管理员切换用户状态开关，**When** 后端拒绝或请求失败，**Then** 开关恢复原状态并展示错误，不出现界面与数据不一致。
7. **Given** 管理员选择多个用户，**When** 执行批量删除，**Then** 成功删除的记录从列表消失；包含当前登录用户或超级管理员等受保护记录时，操作被拒绝并给出明确提示。
8. **Given** 管理员下载导入模板并上传合法文件，**When** 选择“更新已存在用户数据”后提交，**Then** 页面展示导入成功/失败数量与失败原因；上传非法格式时给出可理解的错误。
9. **Given** 管理员点击导出，**When** 导出完成，**Then** 下载文件包含当前筛选条件下的用户数据与约定列。

### User Story 2 - 角色、数据权限与用户授权 (Priority: P1)

系统管理员可以维护角色（角色名称、权限字符、显示顺序、状态、备注），为角色配置菜单权限与数据权限范围，并管理角色下的已授权/未授权用户。角色列表支持按角色名称、权限字符、状态与创建时间筛选和导出。

**Why this priority**: 角色是菜单权限、按钮权限与数据范围的载体。用户管理必须先有角色可分配，菜单与部门授权也必须通过角色落地。

**Independent Test**: 独立创建一个角色，为其勾选菜单、设置数据权限范围、添加/移除授权用户，再使用该角色对应的账号验证可见菜单与数据范围；最后删除角色并确认列表与授权关系同步更新。

**Acceptance Scenarios**:

1. **Given** 管理员进入角色管理页，**When** 按角色名称、权限字符或状态筛选，**Then** 列表与分页结果正确，重置后恢复默认条件。
2. **Given** 管理员新增角色，**When** 填写角色名称、权限字符、顺序、状态并提交，**Then** 新角色出现在列表中；权限字符重复时展示后端错误且不新增。
3. **Given** 管理员编辑角色，**When** 在菜单权限树中勾选/取消菜单并保存，**Then** 重新打开角色时勾选状态保持一致；父子联动开关的行为与勾选结果一致。
4. **Given** 管理员设置角色的数据权限范围，**When** 选择“自定义数据权限”并勾选部门，**Then** 保存后重新打开仍保持所选部门；选择其他范围时部门树按规则显示或隐藏。
5. **Given** 管理员进入角色的用户授权页，**When** 添加未授权用户或移除已授权用户，**Then** 两个列表的数量与内容同步变化，批量操作结果正确。
6. **Given** 角色被用户引用或属于内置管理员角色，**When** 管理员尝试删除或停用，**Then** 系统拒绝并给出明确原因，角色状态不被错误修改。
7. **Given** 管理员点击导出，**When** 导出完成，**Then** 下载文件包含当前筛选条件下的角色数据与约定列。

### User Story 3 - 菜单与权限标识配置 (Priority: P2)

系统管理员可以以树形结构查看和维护菜单，按菜单名称、状态筛选；可以新增目录、菜单、按钮等不同类型的节点，编辑路由地址、组件路径、权限标识、排序、显示/隐藏、缓存、外链等属性，删除单个菜单或级联删除菜单及其子节点。

**Why this priority**: 菜单树决定所有业务页面的可达性与按钮权限标识。它依赖角色授权来生效，但本身可以独立维护与验证。

**Independent Test**: 新增一个目录及其子菜单和按钮，刷新菜单树后结构正确；将菜单分配给角色后对应账号可见；删除子节点或级联删除后树结构与角色授权同步更新。

**Acceptance Scenarios**:

1. **Given** 管理员进入菜单管理页，**When** 按菜单名称或状态筛选，**Then** 树形列表只显示匹配节点及其必要父节点，重置后恢复完整树。
2. **Given** 管理员新增目录、菜单或按钮，**When** 填写该类型必填属性并提交，**Then** 新节点出现在正确父节点下；缺少必填项或属性组合非法时给出校验错误。
3. **Given** 管理员编辑菜单，**When** 修改名称、排序、权限标识、显示状态或缓存设置并保存，**Then** 树形结构与详情立即反映修改。
4. **Given** 菜单存在子节点，**When** 管理员执行普通删除，**Then** 系统按既有规则拒绝或提示；执行级联删除并确认后，该节点及其所有子节点被移除。
5. **Given** 管理员为角色勾选菜单，**When** 保存后使用该角色账号登录，**Then** 仅显示已授权且未隐藏的菜单，按钮权限按权限标识生效。

### User Story 4 - 组织架构（部门）维护 (Priority: P2)

系统管理员可以以树形结构查看和维护部门，按部门名称、类别编码、状态筛选；可以新增下级部门、编辑部门信息（名称、类别、排序、负责人、联系电话、邮箱、状态）、删除部门，并展开/折叠部门树。

**Why this priority**: 部门树是用户归属、数据权限范围和岗位归属的基础。没有部门维护，用户与角色的数据范围无法正确配置。

**Independent Test**: 新增一级部门与下级部门，编辑负责人和状态，刷新后树结构正确；将部门用于用户归属与角色自定义数据权限后，相关选择器可见；删除空部门成功，删除含下级或用户的部门被拒绝。

**Acceptance Scenarios**:

1. **Given** 管理员进入部门管理页，**When** 按部门名称、类别编码或状态筛选，**Then** 树形列表正确过滤，展开/折叠操作不影响筛选结果。
2. **Given** 管理员新增部门，**When** 选择上级部门并填写必填项提交，**Then** 新部门出现在正确层级；同级部门名称重复或上级选择非法时给出明确错误。
3. **Given** 管理员编辑部门，**When** 修改名称、排序、负责人、联系方式或状态并保存，**Then** 树形结构与详情同步更新。
4. **Given** 部门存在下级部门或关联用户，**When** 管理员尝试删除，**Then** 系统拒绝并说明原因；删除无关联的叶子部门成功。
5. **Given** 管理员在用户管理中打开部门选择器，**When** 查看部门树，**Then** 结构与部门管理页一致，已停用部门按既有规则展示。

### User Story 5 - 岗位配置 (Priority: P3)

系统管理员可以按岗位编码、岗位名称、类别编码、所属部门与状态筛选岗位，新增、编辑、删除岗位并导出岗位数据；岗位可作为用户资料的一部分被分配。

**Why this priority**: 岗位是用户资料的扩展属性，依赖用户与部门已可用；业务价值明确但优先级低于用户、角色、菜单和部门。

**Independent Test**: 独立完成岗位的新增、筛选、编辑、启用/停用、导出与删除，并在用户新增/编辑页确认岗位选项同步出现。

**Acceptance Scenarios**:

1. **Given** 管理员进入岗位管理页，**When** 按岗位编码、名称、类别、部门或状态筛选，**Then** 列表与分页结果正确，重置后恢复默认条件。
2. **Given** 管理员新增岗位，**When** 填写岗位名称、编码、类别、所属部门、顺序、状态并提交，**Then** 新岗位出现在列表中；编码重复时展示后端错误且不新增。
3. **Given** 管理员编辑或删除岗位，**When** 操作成功，**Then** 列表即时更新；岗位被用户引用时删除被拒绝并说明原因。
4. **Given** 管理员点击导出，**When** 导出完成，**Then** 下载文件包含当前筛选条件下的岗位数据与约定列。
5. **Given** 管理员在用户新增/编辑页选择岗位，**When** 打开岗位选择器，**Then** 只展示当前可分配的岗位，保存后用户岗位关系正确。

### Edge Cases

- **权限不足**：用户没有某个按钮权限时，按钮不渲染；直接访问隐藏授权页或调用受限操作时，页面展示无权限提示且不泄露数据。
- **超级管理员保护**：内置超级管理员用户与管理员角色不可被删除、停用或剥夺关键权限；尝试操作时给出明确提示。
- **自我操作**：当前登录用户删除自己、停用自己或移除自己的关键角色时，按后端既有规则拒绝并提示。
- **关联数据**：删除仍被用户引用的角色/岗位、仍含下级或用户的部门、仍含子节点的菜单时，系统拒绝并说明被引用情况。
- **重复与格式**：用户名、手机号、邮箱、角色权限字符、岗位编码、部门同级名称等重复或格式非法时，展示后端校验信息，表单保持可修正状态。
- **空数据**：列表、树、授权页在无数据时展示空状态，不出现无限加载或错误弹窗。
- **分页边界**：页码超出范围、每页条数变化、筛选后总数为 0 时，分页组件回到有效状态。
- **请求失败**：列表、详情、保存、删除、导入、导出任一请求失败时，展示可理解的错误；状态开关等乐观交互回滚，不出现“界面成功、数据未变”。
- **会话失效**：操作过程中会话过期时，按统一会话规则回到登录页，不丢失未提交表单以外的数据。
- **导入异常**：导入文件为空、模板列缺失、行数据非法或部分成功时，展示成功/失败统计与可定位的失败原因。
- **树形选择**：菜单树、部门树的父子联动、全选/全不选、展开/折叠在深层节点与半选状态下行为一致。
- **长文本与特殊字符**：名称、备注、路径、权限标识包含长文本或特殊字符时，列表截断/提示正常，保存后内容不被截断或转义错误。

## Requirements *(mandatory)*

### Functional Requirements

**通用列表与交互**

- **FR-001**: 系统 MUST 为用户、角色、菜单、部门、岗位提供与既有系统一致的列表/树形展示、关键字筛选、状态筛选、分页、排序与重置能力；菜单与部门以树形结构展示并支持展开/折叠。
- **FR-002**: 系统 MUST 在新增、编辑、删除、授权、导入、导出、状态切换等操作成功后，使当前视图与后端数据保持一致；操作失败时展示后端返回的可理解错误，并保持表单或列表可继续操作。
- **FR-003**: 系统 MUST 按当前账号的权限标识控制页面入口与操作按钮；无权限的按钮不渲染，直接访问受限页面或执行受限操作时被拒绝且不泄露数据。
- **FR-004**: 系统 MUST 对删除、批量删除、级联删除、重置密码、停用账号、移除授权等敏感操作进行二次确认，并在确认后执行。
- **FR-005**: 系统 MUST 对必填项、长度、格式、枚举值、重复性进行前端校验，并同时处理后端返回的校验错误；前端校验不得替代后端校验。
- **FR-006**: 系统 MUST 为所有列表、树、表单、授权页提供加载中、空数据、请求失败三种状态，避免无限加载或空白无提示。

**用户管理**

- **FR-007**: 系统 MUST 支持按用户名称、用户昵称、手机号码、状态、所属部门、创建时间范围筛选用户，并展示用户编号、用户名称、用户昵称、部门、手机号码、状态、创建时间等约定列。
- **FR-008**: 系统 MUST 支持新增用户，字段至少包括用户昵称、归属部门、手机号码、邮箱、用户名称、用户密码、性别、状态、岗位、角色、备注；用户名称与密码仅在新增时可填写。
- **FR-009**: 系统 MUST 支持编辑用户资料、删除单个/多个用户、重置用户密码、启用/停用用户，并在列表中提供对应操作入口。
- **FR-010**: 系统 MUST 支持为用户分配角色：展示用户当前角色，支持多选保存，并在重新进入时保持授权结果。
- **FR-011**: 系统 MUST 支持下载用户导入模板、上传用户数据、选择是否更新已存在用户，并展示导入结果与失败原因。
- **FR-012**: 系统 MUST 支持按当前筛选条件导出用户数据，导出文件列与列表约定列一致。
- **FR-013**: 系统 MUST 在用户列表提供部门树导航，选择部门后按该部门及其下级部门过滤用户，并支持清空部门筛选。

**角色与授权**

- **FR-014**: 系统 MUST 支持按角色名称、权限字符、状态、创建时间范围筛选角色，并展示角色名称、权限字符、显示顺序、状态、创建时间等约定列。
- **FR-015**: 系统 MUST 支持新增、编辑、删除单个/多个角色，字段至少包括角色名称、权限字符、角色顺序、状态、菜单权限、备注。
- **FR-016**: 系统 MUST 支持为角色配置菜单权限，提供树形勾选、展开/折叠、全选/全不选、父子联动，并在保存后保持勾选结果。
- **FR-017**: 系统 MUST 支持为角色配置数据权限范围，至少覆盖全部数据、自定义数据、本部门数据、本部门及以下数据、仅本人数据等既有范围；选择自定义范围时可勾选部门并保持结果。
- **FR-018**: 系统 MUST 支持查看角色的已授权用户与未授权用户，支持单个/批量添加与移除授权用户，并同步更新两个列表。
- **FR-019**: 系统 MUST 支持启用/停用角色、导出角色数据，并保护内置管理员角色及被引用角色不被非法删除或停用。

**菜单管理**

- **FR-020**: 系统 MUST 支持按菜单名称、状态筛选菜单，并以树形结构展示菜单名称、图标、排序、权限标识、组件路径、状态、创建时间等约定列。
- **FR-021**: 系统 MUST 支持新增目录、菜单、按钮等不同类型的菜单节点，字段至少包括上级菜单、菜单类型、菜单图标、菜单名称、显示排序、路由地址、组件路径、权限标识、路由参数、是否外链、是否缓存、显示状态、菜单状态、激活路径与备注；不同类型按既有规则要求不同必填项。
- **FR-022**: 系统 MUST 支持编辑菜单、删除单个菜单、级联删除菜单及其全部子节点，并在删除前提示影响范围。
- **FR-023**: 系统 MUST 保证菜单的显示/隐藏、状态、外链、缓存、权限标识等属性保存后对动态菜单与按钮权限生效。

**部门管理**

- **FR-024**: 系统 MUST 支持按部门名称、类别编码、状态筛选部门，并以树形结构展示部门名称、类别编码、排序、状态、创建时间等约定列。
- **FR-025**: 系统 MUST 支持新增下级部门、编辑部门、删除部门，字段至少包括上级部门、部门名称、类别编码、显示排序、负责人、联系电话、邮箱、部门状态。
- **FR-026**: 系统 MUST 在部门选择器中排除当前部门及其下级部门，防止形成循环层级；删除含下级部门或关联用户的部门时按既有规则拒绝并说明原因。
- **FR-027**: 系统 MUST 支持部门树的展开/折叠，并保证部门管理页、用户归属选择器、角色数据权限选择器中的部门树结构一致。

**岗位管理**

- **FR-028**: 系统 MUST 支持按岗位编码、岗位名称、类别编码、所属部门、状态筛选岗位，并展示岗位编码、类别编码、岗位名称、部门、排序、状态、创建时间等约定列。
- **FR-029**: 系统 MUST 支持新增、编辑、删除单个/多个岗位，字段至少包括岗位名称、所属部门、岗位编码、类别编码、岗位顺序、状态、备注。
- **FR-030**: 系统 MUST 支持导出岗位数据，并在用户新增/编辑页提供与当前可分配岗位一致的岗位选择器。
- **FR-031**: 系统 MUST 保护被用户引用的岗位不被删除，并在删除失败时说明引用原因。

**数据与一致性**

- **FR-032**: 系统 MUST 以用户、角色、菜单、部门、岗位的既有数据契约为准展示和提交数据；字段名称、类型、可空性、枚举值、空值语义不得由前端自行改变。
- **FR-033**: 系统 MUST 正确处理用户-角色、用户-岗位、角色-菜单、角色-部门、部门-用户、部门-岗位之间的关联关系，任何授权或归属变更后重新查询结果一致。
- **FR-034**: 系统 MUST 保持与既有系统一致的中文文案、状态枚举（如正常/停用）、性别枚举、是否枚举与日期格式；不得自创错误码或错误结构。

- **范围口径**：本需求覆盖后端动态菜单中的 `system/user`、`system/user/authRole`（隐藏授权页）、`system/role`、`system/role/authUser`（隐藏授权页）、`system/menu`、`system/dept`、`system/post`。字典、参数、通知公告、文件、客户端、租户、日志、监控、工具、演示、工作流与任务模块不在本需求内，分别由 REQ-003 至 REQ-006 承接。

- **数据契约**：用户、角色、菜单、部门、岗位的字段与语义以现有后端返回和既有类型定义为基线；空值、可空性、日期格式、状态/性别/是否枚举沿用既有约定。

- **交互基线**：列表默认分页、筛选条件在重置后恢复默认值；删除与批量操作使用二次确认；树形选择支持父子联动与半选状态；导入使用后端提供的模板与结果统计。
