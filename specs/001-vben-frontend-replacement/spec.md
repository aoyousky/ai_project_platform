# Feature Specification: 前端框架替换（Vben 前端外壳）

**Feature Branch**: `001-vben-frontend-replacement`

**Created**: 2026-11-01

**Status**: Draft

**Input**: User description: "前端框架替换：将 frontend/ 的 plus-ui（Vue 3 + Element Plus + npm）替换为 Vben Admin 5.7.0 的 apps/web-antdv-next（antdv-next 1.3.0 + pnpm），后端 platform/ 零改动。适配范围：RSA+AES 加密登录与图形验证码、后端 getRouters 菜单转 Vue Router、分页响应体 {code,msg,rows,total}、超管权限码 *:*:* 通配、外链菜单 IFrameView 内嵌、/index 常量路由。依据 docs/adr/002-frontend-vben-adapter.md 与 clarifications/CLAR-001.md 的 2026-11-01 裁决。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用现有账号登录并进入首页 (Priority: P1)

运营与业务人员在浏览器打开平台，输入现有的用户名、密码与图形验证码，登录成功后直接进入首页，
看到与自己权限相符的侧边菜单，整个过程不需要学习任何新操作。

**Why this priority**: 登录是进入系统的唯一入口，没有它其余能力都无法验收；同时它覆盖了最容易被
框架替换破坏的一层——加密传输与验证码。

**Independent Test**: 用一套后端账号在全新前端完成"打开登录页 → 输错验证码 → 重新输入 → 登录成功 →
落在首页"的完整链路，即可独立验证并交付价值。

**Acceptance Scenarios**:

1. **Given** 用户未登录，**When** 打开平台根地址，**Then** 看到登录页，包含用户名、密码、图形验证码三个输入项，
   不出现"手机号登录""扫码登录"等平台不具备的入口。
2. **Given** 登录页已显示验证码，**When** 用户输入正确的用户名、密码与验证码，**Then** 登录成功并落在首页，
   菜单区显示该账号有权访问的菜单。
3. **Given** 用户输入了错误的验证码，**When** 提交，**Then** 停留在登录页并以人可读的提示告知失败原因，
   验证码自动刷新，已填写的用户名保留。
4. **Given** 用户已登录但令牌过期，**When** 触发任意需要登录的操作，**Then** 系统回到登录页（或提示重新登录），
   不出现空白页或循环跳转。

---

### User Story 2 - 按权限看到菜单与操作按钮 (Priority: P1)

普通用户只看到自己被授予的菜单和操作按钮；系统管理员（超级管理员）看到全部菜单与按钮。
菜单结构由后端统一配置，前端不保存任何硬编码菜单。

**Why this priority**: 权限呈现错误会导致越权操作入口或功能不可见，属于安全与可用性的双重底线。

**Independent Test**: 分别用普通账号与超级管理员账号登录，比对侧边菜单与页面内按钮的可见集合，
即可独立验证。

**Acceptance Scenarios**:

1. **Given** 后端返回的菜单包含有权限与无权限两类节点，**When** 用户登录，**Then** 菜单只渲染该账号被授权的那部分，
   层级与排序与后端配置一致。
2. **Given** 用户的权限集合为平台约定的"全部权限"通配值，**When** 进入任一业务页面，**Then** 页面内所有受控按钮
   （新增、修改、删除、导出等）均可见，不会出现"管理员看不到按钮"。
3. **Given** 用户缺少某个操作权限，**When** 进入对应页面，**Then** 页面可访问但该按钮不可见。
4. **Given** 用户直接在地址栏输入一个未授权页面的地址，**When** 访问，**Then** 被引导到 403/404 提示页，
   不渲染页面内容。

---

### User Story 3 - 外链菜单在系统内嵌打开 (Priority: P2)

后端菜单中可以配置外部网址（如厂商官网、外部工具）。用户点击这类菜单时，外部页面在当前系统的
内容区内嵌打开，而不是跳出系统或打开一个空白页。

**Why this priority**: 外链菜单是既有配置能力的延续，缺失会让部分菜单"消失"；但它不影响核心业务操作。

**Independent Test**: 在一个配置了外链菜单的账号下登录，点击该菜单，检查内容区是否出现内嵌页面
且系统导航（菜单、标签页）仍然可用。

**Acceptance Scenarios**:

1. **Given** 后端菜单中存在一个外部网址菜单项，**When** 用户登录，**Then** 该菜单项出现在侧边菜单中，
   位置与后端配置一致。
2. **Given** 用户点击外部网址菜单项，**When** 页面加载完成，**Then** 内容区以内嵌方式显示目标网址，
   地址栏地址为系统内部的稳定路径，标签页出现该菜单。
3. **Given** 目标网址禁止被内嵌（站点自身限制），**When** 用户打开该菜单，**Then** 系统其他部分正常工作，
   不出现整站白屏或路由崩溃；用户可手动在新窗口打开目标地址。

---

### User Story 4 - 标准业务页面在新前端功能一致 (Priority: P2)

以"岗位管理"为样例的典型业务页面（搜索、分页列表、新增、修改、批量删除、字典项展示）
在新前端下与原系统行为一致，并作为其余页面的移植范式。

**Why this priority**: 框架替换的最终价值体现在业务页面可用；样例页先跑通，才能批量移植其余页面。

**Independent Test**: 在样例页完成"搜索 → 新增 → 列表出现 → 修改 → 删除 → 列表消失"的闭环，
数据与后端一致。

**Acceptance Scenarios**:

1. **Given** 用户有查看权限，**When** 打开岗位管理页，**Then** 列表按后端分页返回数据，
   分页器显示的总数、页数与后端返回一致。
2. **Given** 用户点击"新增"并填写必填项，**When** 确认，**Then** 数据保存成功，列表刷新后可见新记录。
3. **Given** 用户勾选若干行点击"批量删除"，**When** 确认，**Then** 这些记录被删除，列表刷新后不再出现。
4. **Given** 后端返回业务失败（如校验不通过），**When** 用户提交，**Then** 界面显示后端返回的提示文案，
   不显示技术性报错（堆栈、HTTP 状态码原文）。

---

### Edge Cases

- **验证码过期**：用户停留过久后提交，验证码失效 → 提示失败并自动刷新验证码，不清空用户名。
- **后端菜单为空**：账号无任何菜单 → 登录成功但显示空菜单与引导页，不出现报错或无限加载。
- **后端菜单含隐藏项**：隐藏菜单不出现在侧边栏，但仍可被程序化跳转访问。
- **路由名或路径重复**：后端配置了重名菜单 → 该菜单项不可用但其余菜单正常，不得导致整张菜单渲染失败。
- **未移植页面**：菜单指向尚未移植的页面 → 显示统一的"建设中/404"占位页，菜单其余部分可正常使用。
- **外链网址变更**：后端把外链改到新地址 → 用户刷新后内嵌地址随之更新，无需发布前端。
- **登出**：退出登录后回到登录页，再次进入需要重新认证，浏览器回退不能回到已登录页面。
- **通知/标签页**：多标签页打开同一系统 → 任一处登出后，其他标签页在下次操作时要求重新登录。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供与现有后端完全兼容的登录入口，用户名、密码、图形验证码登录后进入首页。
- **FR-002**: 系统 MUST 在与后端交互过程中保持既有的传输加密约定（登录请求体加密、按服务端指示解密响应），
  并不得把加密密钥写进前端仓库以外的位置或日志。
- **FR-003**: 系统 MUST 在服务端令牌失效时把用户送回登录页，不出现白屏、循环跳转或残留已登录界面。
- **FR-004**: 系统 MUST 在用户主动登出后清除本地会话，浏览器回退不得恢复到已登录界面。
- **FR-005**: 系统 MUST 从后端一次性取得该用户的菜单与路由，前端不保存任何业务菜单的硬编码副本。
- **FR-006**: 系统 MUST 按后端配置渲染菜单层级、顺序、图标、隐藏标记与缓存标记。
- **FR-007**: 系统 MUST 支持后端约定的"全部权限"通配值：持有该值的账号在按钮级控制上视为拥有全部权限。
- **FR-008**: 系统 MUST 对未授权页面路由返回 403/404 提示页，不渲染页面内容。
- **FR-009**: 系统 MUST 把后端配置的外部网址菜单渲染为可点击菜单项，并在系统内容区内嵌打开该网址。
- **FR-010**: 系统 MUST 保证单个异常菜单项（外链、重复名、缺组件）只影响自身，不影响其余菜单与路由。
- **FR-011**: 系统 MUST 正确解析后端两种响应形态：单对象响应与分页列表响应；分页页数与总数以后端为准。
- **FR-012**: 系统 MUST 把后端返回的业务错误文案原样展示给用户，不展示堆栈或自定义错误结构。
- **FR-013**: 系统 MUST 在框架替换完成后，与现有后端接口契约保持一致，不修改任何后端接口、字段或错误码。
- **FR-014**: 系统 MUST 为每个移植页面提供自动化测试，覆盖"列表加载、新增、修改、删除"中该页面具备的操作，
  测试需先失败后通过（RED→GREEN）。
- **FR-015**: 系统 MUST 保留首页作为登录后的默认落点，且首页不依赖后端菜单配置即可访问。
- **FR-016**: 系统 MUST 支持浏览器刷新后维持当前页面（深层地址可直接访问，不丢失登录态与菜单）。
- **FR-017**: 系统 MUST 在首次进入时按用户偏好（主题、语言）渲染界面，偏好需在会话间保持。

### Key Entities *(include if feature involves data)*

- **用户会话**：登录后的一组凭据与用户画像（显示名、头像、所属部门、角色、权限集合），决定可见菜单与按钮。
- **菜单项**：后端下发的导航节点，含标题、图标、路径、层级、是否隐藏、是否缓存、关联页面组件；外链菜单额外携带外部网址。
- **权限码**：操作级授权标识（如"岗位新增"），与页面内按钮一一对应；平台保留一个"全部"通配值。
- **业务记录（样例：岗位）**：典型的 CRUD 数据，具备编码、名称、所属部门、排序、状态、备注等字段，用于验证列表与增删改。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 熟练用户从打开登录页到进入首页不超过 60 秒（含人工输入验证码）。
- **SC-002**: 后端配置的菜单项在新前端的呈现覆盖率为 100%——除"隐藏"标记外，每一条后端菜单都能在侧边栏找到并打开。
- **SC-003**: 超级管理员账号在任一业务页面上，受控按钮可见率为 100%；普通账号的越权按钮可见率为 0。
- **SC-004**: 框架替换期间后端接口变更数为 0（接口路径、字段、错误码均不变）。
- **SC-005**: 已移植页面中，至少 90% 具备列表与增删改的自动化测试，且全部为 RED→GREEN 证据。
- **SC-006**: 登录后进入首页的可见加载时间（可交互）不超过 3 秒（本地环境、常规网络）。
- **SC-007**: 页面级失败率：连续点击全部菜单项，因前端原因导致的页面崩溃为 0；无法访问的页面均给出明确占位提示。
- **SC-008**: 交付后 30 天内，与"前端无法登录/菜单缺失/按钮不显示"相关的缺陷工单数为 0。

## Assumptions

- **框架选型已定**：前端底座为 Vben Admin 5.7.0 `apps/web-antdv-next` + antdv-next，包管理器为 pnpm，
  来源与只读约束见 `docs/adr/002-frontend-vben-adapter.md`；本规格只描述行为，不重新评估选型。
- **后端零改动**：`platform/` 的接口、数据契约、权限码与错误码保持现状；所有差异在前端适配层消化。
- **登录方式不变**：沿用用户名 + 密码 + 图形验证码；平台不具备手机号登录与扫码登录，因此不提供这两种入口。
- **权限模型不变**：按钮级权限沿用后端的权限码集合与"全部权限"通配值；不引入前端自建角色体系。
- **外链菜单**：按 PM 裁决使用内嵌打开；目标站点若设置防嵌套策略导致内容无法显示，由菜单运营方改配可内嵌地址，
  前端不做自动降级（保留标签页，用户可另行在新窗口打开）。
- **页面范围**：以"岗位管理"作为标准 CRUD 样例页先行；其余菜单承载的页面按限界上下文分批移植，
  未移植页面显示统一占位页，不阻塞本规格的验收。
- **工作流页面**（流程设计器、动态表单、任务列表）工作量与风险最高，单独评估，不在本规格的首批交付范围内。
- **浏览器范围**：现代常青浏览器（Chrome/Edge 最新两个大版本），不承诺旧版 IE/Edge Legacy。
- **主题与语言**：沿用新前端默认主题与中文文案；多语言资源按框架能力保留，不新增翻译工作量。
- **测试环境**：本地 Docker 后端栈（MySQL/Redis）可用，测试账号由后端预置。
- **迁移期并存**：旧前端代码在新前端通过验收前保留只读；验收通过后按 PM 裁决直接删除，不打归档 tag。
