# 变更记录

## v1.1.0 — 2026-11-10

针对「内部团队门禁」场景的可用性加固。目标是让误报率低到没人绕过、关键项能卡住 CI。

### 新增

- `eval/prd_forge_eval.py`：26 用例回归评测集，基于「合格文档 + 定点变异」，分 positive / planted / gap / semantic 四类。变异带锚点断言，防止改不到目标却显示通过。
- `--strict`：WARN 也判定为未通过，供 CI 卡点使用。
- `--allow "术语1,术语2"`：豁免团队内部术语，避免被模糊词表误伤。
- W114：形似需求标题但未被识别的行（`#### FR-001`、`### FR001` 等），堵住「换标题层级绕过门禁」的口子。
- `SKILL.md` 增加 `version` 字段；本变更记录。

### 修复

| 缺陷 | 症状 | 根因 |
|---|---|---|
| E006 误拦截 | 验收标准写 `1. Given ...` 直接判 ERROR | 只认 `- [ ]` 复选框 |
| E001 误拦截 | `## 3 功能需求` 缺句点被判为缺章 | 章标题正则强制要求句点 |
| 需求被静默跳过 | `#### FR-001` 的缺陷查不出，可绕过门禁 | FR 正则只认三级标题 |
| W109 永不生效 | 指标全是形容词也不报 | 数字判定包含章标题，「## 1.」自带数字 |
| W112 漏检 | 用户故事写成陈述句不报 | 要求句中含「作为」才检查 |
| E009 放过空骨架 | 空模板 73 分仍判定通过 | 阈值 10 过高，且含 Given 的行被整体跳过 |
| W106 误报 | 「提升额度」「查询优化器」被判为模糊词 | 中文裸子串匹配，无词边界 |
| E006 范围过宽 | 业务规则的列表项被算进验收标准 | 条目统计未收敛到「验收标准」字段之后 |

### 评测基线

| 指标 | v1.0 | v1.1.0 |
|---|---|---|
| 合格文档不被误判 | 2/5（误报率 60%） | **5/5（误报率 0%）** |
| 规则集内缺陷检出 | 13/13（8/8 拦截） | **15/15（10/10 拦截）** |
| 规则集外缺口检出 | 1/6 | 2/5 |
| 语义缺陷检出 | 0/2 | 0/2（能力边界，未改善） |

语义层的 0/2 是设计边界而非缺陷：脚本判断不了「两条需求互相矛盾」。这层只能靠 L3 独立评审，方法见 `references/quality-verification.md`。

## v1.0 — 2026-11-10
