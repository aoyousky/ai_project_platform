---
description: STOP 机制：把当前歧义写成澄清问题单，等待 PM 裁决
---

基于对话中最近一次 `⚠️ STOP: CLAR` 输出（或 `$ARGUMENTS` 描述的歧义），生成澄清问题单文件 `clarifications/CLAR-<下一个序号>.md`，模板：

```markdown
# CLAR-XXX

- REQ: <需求编号>
- TRIGGER: <断言/边界/契约字段>
- STATUS: 待裁决        # 待裁决 / 已裁决 / 已回写 Spec
- RAISED_BY: agent
- DATE: <今天日期>

## 歧义描述
<两种理解分别是什么>

## 影响对比
| 选项 | 行为 | 影响的断言 |
|---|---|---|
| A | | |
| B | | |

## Agent 默认假设（仅供参考，未经裁决不得据此交付）
<...>

## PM 裁决
<裁决结果；是否升版 Spec Packet：是/否，升版后版本号：>
```

写完文件后，向用户复述问题单要点，并明确说明：**在该条目裁决前，相关实现已冻结**。不要基于默认假设继续写代码。
