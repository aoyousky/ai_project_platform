对 `$ARGUMENTS` 指定的 SPEC 做体检，输出**分数 + 缺口 + 可直接粘贴的改写建议**。

## 定位（关键，不要越界）

- 本命令**不判定通过与否**。门禁的 PASS/FAIL 只由 `scripts/ci-gate.sh` 决定
- 本命令**不修改** `specs/*.md` 原文件。改写建议写进 `specs/_audit/<id>.md`
- 若用户主动要求"帮我改"，只能改 `specs/_drafts/` 下的草稿，且改前逐条确认

## 执行步骤

1. 跑客观体检：
   ```bash
   bash scripts/spec-audit.sh <目标文件>
   ```
   拿到分数、分项、缺口清单、模糊词行号。**先原样呈现脚本结果**，不要用你的判断覆盖它。

2. **定位到现有门禁的失败项**（这是本命令最有价值的用法）。
   同时跑一次门禁看当前状态：
   ```bash
   bash scripts/ci-gate.sh specs 2>&1 | tail -20
   ```
   若门禁有 FAIL，逐项翻译成改写动作：
   | 门禁失败 | 辅助动作 |
   |---|---|
   | 门禁 1 禁词 | 列出每个禁词所在行，给出该句的"数字版/断言版"替换文本 |
   | 门禁 2 异常条数 < 断言 | 按缺失的边界类别（空/超限/幂等/权限/超时/非法状态）生成候选 E-xx，标注"需业务确认" |
   | 门禁 3 溯源缺失 | 提示走 `/trace`，不代写（溯源必须人工确认审阅人） |
   | 门禁 5 评测集未过 | 只做失败用例 → 断言编号的反查，指出是规格问题还是实现问题 |

3. 对扣分最重的 3 个维度，各给 **1–2 条具体改写**，格式固定：

   ```
   ▸ <维度>（当前 <得分>/<满分>）
   L<行号> 原文：<原句>
   改为：<可直接替换的句子>
   为什么：<一句话说清判定标准>
   ```

   改写必须满足：数字化、可判定、不给 AI 留选择空间。

4. 生成报告 `specs/_audit/<id>-<时间戳>.md`，包含：分数、分项、缺口、改写建议、模糊词清单。

5. 结尾固定输出：

   ```
   就绪度 <分数>/100 〔<档位>〕
   门禁状态：<原样引用 ci-gate.sh 结论>
   报告：specs/_audit/<文件>
   提醒：分数不用于合并判定；只有 ci-gate.sh 的退出码具有阻断效力。
   ```

## 禁止事项

- 禁止说"体检未通过，不能提交"——辅助层没有这个权力
- 禁止把分数写进 SPEC 或 trace（会污染交付依据）
- 禁止只报分数不给缺口清单（分数会诱使人刷分，清单才能改进质量）
- 禁止臆造业务规则来填缺口；拿不准的标 `⚠️ 需业务确认`
